# 印刷厂 · 印版与工单

厂里的台账：**印刷机**、**印版**、**纸张**、**印刷工单**。

两个业务重点：
- **工单按工序走**：待印 → 印刷中 → 已完成，跳步和回退都会被拦；开单前会看**指定的纸够不够**、
  **指定的印版有没有作废**。纸张库存按克重折算，罩不住这批份数就不让开。
- **多条件叠加查询**：客户、状态、用纸、交期区间任意组合，条件给了才拼进 SQL（见 `spec/PrintJobSpecs`），
  页面顶上用条件胶囊把当前生效的条件摆出来。
- **校色试印台账卡上机**：待印单没有「通过」的试印记录就不许推进印刷中（页面和后台都拦）；
  记「通过」那一刻版必须正好装在指定机台上、机器在跑、版在用；推进时按**眼下**的装版和机态重核，
  版挪了、机停了、版废了，旧通过只留档备查，不再当通行证。
- **延误桌一张桌摊三件事**（`service/DelayDeskService` + `/api/delay-desk`）：交期、纸、版
  每次拉桌按当天日期和眼下状态**现算，不落快照**——
  过了交期当天的待印/印刷中单上桌（已完成、交期在未来的不进）；逾期 **> 3 天**加急；
  指定纸**缺货**或指定版**已磨损**，哪怕只逾期一天也加急，并写清「纸拖的/版拖的」。
  改交期回未来当场离桌、天数跟着新日子走；补了货、修了版，只因此加急的自动退回普通延误。

## 技术栈

- 后端：Spring Boot 3.3 / Java 17、Spring Data JPA（**工单查询用 Specification 动态拼条件**）、MySQL 8、Redis 7
- 前端：Vue 3（Composition API + **一个十几行的自实现事件总线** `utils/bus.js`，
  改完数据广播 `data-changed`）+ Element Plus + Vite
- 一键起：`./start.sh`

## 业务模块

1. **印刷机**（`press`）—— 编号名称型号、机长、运行/停机/封存（封存前要求先卸版）
2. **印版**（`plate`）—— 编号版面尺寸、装在哪个机器上、在用/已磨损/已作废
3. **纸张**（`paper`）—— 纸号纸名克重、库存与预警线、充足/紧张/缺货
4. **印刷工单**（`print_job`）—— 客户、用纸、印版、份数、交期、三态流转
5. **校色试印**（`test_print`）—— 工单+印版+印刷机三样齐了才入账，只许挂在待印单上；
   同一张待印单眼下只认最新一条「通过」（落账时先锁工单行，两人同时落只留先到的）
6. **延误桌**（`delay-desk`，只算不存）—— 一张桌同时读到交期、纸、版，
   见上节和 `dto/DelayDeskRow`、`service/DelayDeskService`
